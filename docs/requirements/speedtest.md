
# 浏览器测速页面 + VPS 测速服务
手机或电脑打开页面后，直接与 VPS 传输数据，就能测量这条线路的延迟、上传和下载速度。

其中，**普通网页无法直接测量 ICMP 丢包率**，只能统计测试请求的超时或失败率。页面应标注为“请求失败率”，避免把它误认为真实网络丢包。

### 1. 整体结构

最简单的方式是将页面和接口部署在目标 VPS：

```text
当前设备的浏览器
       ↓ HTTPS 直连
远程 VPS：Nginx
       ├── 静态测速页面
       └── 测速服务：Go
```

### 2. 四项指标如何测量

| 指标 | 实现方法 | 结果含义 |
|---|---|---|
| 延迟 | 在已建立的 WebSocket 上发送带序号的小消息，VPS 原样回传 | 应用层往返延迟，包含网络和服务处理时间 |
| 下载 | 浏览器持续接收 VPS 返回的二进制数据，统计字节数和时间 | VPS → 当前设备的实际吞吐量 |
| 上传 | 浏览器上传二进制数据，VPS 统计实际收到的字节数并确认 | 当前设备 → VPS 的实际吞吐量 |
| “丢包” | 统计回显消息超时、请求失败的比例 | 应标为“请求失败率”，不是 IP 层丢包率 |

WebSocket 基于 TCP，底层丢包通常会触发重传，表现为延迟上升或速度下降。因此，**请求失败率为 0%，也不代表网络没有丢包**。

### 3. 服务端接口设计

需要以下接口：

| 接口 | 作用 |
|---|---|
| `GET /api/info` | 返回节点名称、客户端出口 IP、IPv4/IPv6 |
| `WSS /api/echo` | 回传测试消息，测延迟及超时率 |
| `GET /api/download` | 流式输出不可压缩的二进制测试数据 |
| `POST /api/upload` | 流式接收并丢弃数据，返回实际接收字节数 |

下载数据应提前生成并循环发送，避免实时生成随机数据导致 CPU 成为瓶颈。上传数据无需保存到磁盘。

测速公式：

```text
速率 Mbps = 实际传输字节数 × 8 ÷ 测试秒数 ÷ 1,000,000

请求失败率 = 失败或超时次数 ÷ 总测试次数 × 100%
```

**上传速度必须使用服务端确认收到的数据量**，不能把浏览器已写入发送缓冲区的数据量当作实际上传量。

### 4. 点击“开始测试”后的流程

一次完整测试约 30 秒：

1. **连接与预热**：建立连接，首次握手耗时单独记录。
2. **空闲延迟**：连续测量 20 次，展示中位数、P95、抖动和请求失败率。
3. **下载测试**：持续 10 秒，统计实时速度和平均速度。
4. **上传测试**：持续 10 秒，统计服务端确认的实际上传速度。
5. **显示结果**：支持重新测试和复制结果。

上传、下载时还可以继续发送小型回显消息，额外展示“负载延迟”，方便发现跑满带宽后网络是否变卡。它应与空闲延迟分开显示。

第一版采用单连接测速；后续如果要测线路的最大吞吐量，再增加多连接模式，并在结果中注明连接数。
